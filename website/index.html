02 — THE TYPE SYSTEM

Void is a real type.
APIs can treat it like one.

Void has one logical value and can be used as a type argument. That lets the same generic API represent a useful result or completion without a payload.

Func<T, void> expresses a callback with no useful result. neoCLR uses one Func family, including Func<Void> and Func<T, Void>, where .NET uses Action. Result<Void, E> similarly represents completion or a recoverable error.

The Raven sample spells the unit type System.Void. Ordinary void-returning calls still leave no result on the IL stack; the compiler bridges the unit-value contexts.

03 — THE RUNTIME CLASS LIBRARY

Modernized APIs.
Explicit outcomes.

The class library is where platform improvements become everyday programming. Option and Result make outcomes explicit; collections and date/time APIs explore clearer contracts. The preview makes these ideas usable today, and your feedback can shape their evolution.

01 / OUTCOMES

Result instead of exceptions

Result<T, E> gives recoverable failures a typed return path. Raven’s ? propagates them. Terminal runtime faults remain separate.

02 / ABSENCE

Option instead of null

Option<T> expresses absence as None and presence as Some(value), including zero or an empty string. Optional API outcomes need no null or default-value sentinel; this does not remove null from the runtime.

06 — A PATH FROM FAMILIAR TOOLS

Raven is the first
language target.

Raven is a compiler we can shape to target neoCLR while preserving its normal .NET target. That makes it a practical starting point for exploring a different runtime through a familiar language and toolchain.

The compiler and editor tooling run on .NET. Programs built for the neoCLR target execute on neoCLR, whose interpreter does not require .NET.

Follow the Raven walkthrough →

A migration path to build on

Reuse knowledge of CLR types, assemblies and APIs. Adapt code where neoCLR intentionally differs—especially Option, Result, Void callbacks and mutable array variance. The preview imports a bounded subset; unchanged .NET applications are not a supported migration path yet.

Tooling from the start

The matching experimental Raven VS Code extension provides completion and hover. Dedicated neoCLR build and run tasks connect the source project to the runtime.

07 — WHAT’S NEXT

Build the library in Raven.
Fill out the platform.

The next development goals connect the implementation language with the APIs developers need. These are planned work, not additions already included in the preview.

Move the class library from neoIL to Raven

Make Raven the ordinary source language for the runtime class library, retaining neoIL where low-level implementation needs it. This follows the role of C# in .NET’s libraries and will exercise compiler and importer support for library bodies.

Know the boundaries

This is a proof of concept, not a production runtime or a drop-in .NET replacement. The Raven importer supports bounded application classes, interfaces, inheritance and lambda captures. Generic application hierarchies, unrestricted reflection, nullable metadata and cleanup during terminal faults remain outside its current scope. The dedicated neoCLR tasks provide build/run; the normal Raven toolbar does not implement this target.

The earlier Neo concept language is preserved as development history. Raven is the language used for the current integration.
